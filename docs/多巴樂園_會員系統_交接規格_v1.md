## 1. 登入方式

**只做 Google 與 LINE 兩種社群登入，不做 email／密碼註冊。**
理由：不存密碼＝不用處理雜湊、重設信、外洩責任。若日後要加 email 登入，users 表已預留 `provider` 欄位可擴充。

### OAuth 注意事項

- **Scope 取最小**：只要基本識別（Google: `openid email profile`／LINE: `profile openid`）。
  ⚠️ **登入頁文案已對使用者承諾「不會拿你的社群帳號發文，也不會抓你的好友名單」**——請不要申請任何額外權限，這是寫在畫面上的承諾。
- **LINE Login 與 LINE 官方帳號（OA）**：通知走 LINE OA（見規劃書 §6），LINE Login channel 可與 OA 綁定，讓使用者登入後同時成為 OA 好友。若採此做法，`line_links` 表可省略。
- **同一人用兩種 provider 登入**：v1 視為**兩個帳號**（不做自動合併，避免用 email 猜同一人猜錯）。若 Google 回傳的 email 與既有帳號相同，可在畫面上提示，但不要自動合併。
- 回呼後建立 session（建議 HttpOnly + Secure + SameSite=Lax cookie），前端不碰 token。

### 2.8 `threads`（對話線）＋ `messages`

`threads`

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | uuid PK | |
| `user_a_id` / `user_b_id` | uuid FK | |
| `turn_user_id` | uuid | **輪流制核心**：只有這個人能發言 |
| `status` | enum('open','ended','blocked') | |
| `ended_by` / `ended_at` | | ⚠️ 結束**不通知對方**（規劃書 §11.4） |
| `created_at` | timestamptz | |

`messages`

| 欄位 | 型別 | 說明 |
|---|---|---|
| `id` | uuid PK | |
| `thread_id` | uuid FK | |
| `sender_id` | uuid FK | |
| `body` | varchar(200) | 200 字上限 |
| `created_at` | timestamptz | |

📜 **私訊不審**（政策 3.／條款 7.）：
- **不要建審核佇列、不要做內容掃描、不要有後台介面可以瀏覽 messages。**
- 存取權限只開給「該 thread 的兩位使用者」。
- 唯一的例外是 `reports.evidence`（檢舉人自己交出來的快照）與法律要求。
- 這不是可選的實作偏好，是**寫在隱私權政策上的承諾**。

**發訊規則（後端必須驗證，前端擋不算數）**：
1. `thread.status === 'open'`
2. `sender_id === thread.turn_user_id`（不是你的回合就拒絕）
3. `body.length <= 200`
4. 發送成功後 `turn_user_id` 換人

**即時推送**：Supabase Realtime／Firebase 皆內建，訂閱該 thread 即可。

`user_id`, `line_user_id`, `linked_at`。若 LINE Login 與 OA 綁在同一個 channel，可省略。

## 3. 前端等待的 API

程式碼中 `TODO(後端)` 標記處對應：

**帳號**
- `GET /auth/google`・`GET /auth/line` → 導去 provider 授權頁
- `GET /auth/callback/:provider` → 建立／登入使用者、發 session、導回網站
- `GET /api/me` → 目前登入者（含 nick / nick_status / type / entitlements）
- `PATCH /api/me` `{ nick }` → 送審暱稱（回 `nick_status:'pending'`）
- `POST /api/logout`
- `DELETE /api/me` → 軟刪除，30 天內硬刪
- `POST /api/line/link` → LINE OA 綁定

**大廳**
- `GET/POST /api/lounge/posts`（樹洞，先審後顯）
- `GET /api/matches/daily`（摩天輪：每天 10 位）
- `GET /api/matches/draw`（雲霄：每天 1 位，**限流在後端**）

**信箱**
- `GET /api/invites`・`POST /api/invites`・`POST /api/invites/:id/accept`・`POST /api/invites/:id/decline`
- `GET /api/threads`・`GET /api/threads/:id/messages`
- `POST /api/threads/:id/messages`（驗證輪流制與字數）
- `POST /api/threads/:id/end`・`POST /api/blocks`・`POST /api/reports`

**金流**
- `POST /api/orders` → 建立訂單（**必帶 `cooling_off_ack`**）
- `POST /api/payments/callback` → 金流回呼，成功則寫入 `entitlements`
